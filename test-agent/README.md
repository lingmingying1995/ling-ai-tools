# test-agent · AI 代码测试员

AI 改完代码后，自动检查"改了A没改B"的遗漏，只报告问题不修复。

## 解决什么问题

让 AI 帮你改代码，最怕的就是改了前端没改后端、改了字段名没改引用、删了文件没删链接。AI 自己不会主动检查这些，你得自己一条条扫——累，而且容易漏。

这个 agent 就是替你干这件事的。每次 AI 改完代码，它自动扫一遍所有关联的地方，把遗漏列成清单告诉你。

## 它怎么工作

1. AI（主 agent）改完代码
2. 你说"测一下"或"测试一下"
3. 测试 agent 接手，检查这些维度：
   - **引用一致性**：字段名、文件路径、函数名有没有改漏
   - **接口对应**：后端删了接口前端还在调？前端调了后端不存在的接口？
   - **页面完整性**：有菜单项没页面定义？有页面定义没渲染逻辑？
   - **数据流完整性**：后端返回的字段前端有没有用到？
   - **文件引用**：文档里引用的路径还存在吗？
4. 输出问题清单（指明文件和行号），你让 AI 按清单修

## 怎么装

### 用 opencode 的人

1. 把 `code-tester.md` 复制到你的 agents 目录：
   ```
   ~/.config/opencode/agents/code-tester.md
   ```
2. 完事。下次对 AI 说"测一下"就会触发

### 用其他 AI 工具的人

把 `code-tester.md` 的内容放到你工具的规则文件里（Cursor 的 `.cursorrules`、Claude Code 的 `CLAUDE.md` 等），按你的工具调整触发方式。

核心是让 AI 在改完代码后，按这个清单扫一遍关联模块。

## 配套说明

### 它只报告，不修复

测试 agent 发现问题后只输出清单，修复交给主 agent（或你自己）。这是故意的——检查和修复分开，避免"自己查自己"的盲区。

### 它看不到页面

它只能做静态检查（搜索代码、调接口看返回），看不到页面渲染效果。所以它的报告里会列一个"建议你肉眼验证的清单"，比如"刷新页面确认能看到5条记录"。

### 检查范围可调

- **增量测试**：每次改动后，只查改动涉及的模块（默认）
- **全量测试**：说"全量测试"时，所有模块都过一遍（建议每周一次）

## 它的检查清单

完整的检查清单见 `code-tester.md` 里的"检查清单"章节，有 5 个维度共 16 个检查项。你可以根据自己的项目调整检查项。
